THE NON-NEGOTIABLE RULE

No real generation means no experimental result. A prompt, theory, screenshot, anecdote, or unusually good song can define a test, but it cannot by itself establish causality or reproducibility.

EVIDENCE LADDER

A — Official: current Suno documentation or product behavior explicitly documented by Suno.

B — Repeated community evidence: multiple independent observations that point in the same direction, still not equivalent to official documentation.

C — Controlled reproducible result: one variable isolated, conditions recorded, multiple generations compared, repetitions completed, and competing explanations considered.

D — Hypothesis: a plausible interpretation that still needs controlled testing.

E — Experimental input: intentionally unusual material such as symbols, gibberish, contradictory instructions, or invented syntax used as a probe.

UNTESTED: the protocol exists, but no real generation evidence has been entered.

STANDARD CONDITIONS

Record the exact model name shown in Suno.
Record model branch: V6 / V6-WILD / V6-MINI.
Record Weirdness, Variety, Style Influence and Audio Influence.
Record Max Mode and Personalize state.
Record duration and vocal gender when relevant.
Preserve exact Style, Lyrics, Exclude and structure cues.
Record every reference input.
Record the single variable being changed.
Keep unrelated conditions constant whenever possible.

MINIMUM EXPERIMENT DESIGN

  1. Define one falsifiable question.
  2. Create a control condition.
  3. Create a test condition differing by one intended variable.
  4. Generate multiple samples rather than judging one lucky output.
  5. Log failures and timestamps, not only successes.
  6. Repeat the comparison.
  7. Run cross-song replication when the claim is intended to generalize.
  8. Consider plausible alternative explanations.
  9. Only then assign an evidence status.

SCORING MATRIX

Prompt adherence       0–5

Instrumentation        0–5
Dynamics                0–5
Mix clarity             0–5
Section consistency     0–5
Failure count           record separately
Unexpected behavior     record separately

Do not use the total score as proof of causality.
It is a comparison aid between controlled conditions.

FAILURE CORPUS

Log concrete failures: buried vocal, wrong vocal texture, changed register, chorus arriving early, disappearing instruments, genre drift, late-song degradation, excessive reverb, weak low end, clipped ending, repeated-phrase corruption, ignored section direction, unintended doubles/choir, or unexpected arrangement changes.

For every failure, record what happened, where it happened, under which condition, and whether it repeated.

REPLICATION STANDARD

A finding should not become C-level evidence because three outputs sound similar. The relevant effect must track the manipulated variable better than plausible competing explanations do.

REPEAT #1: same song / same conditions
REPEAT #2: same song / same conditions
REPEAT #3: same song / same conditions
CROSS-SONG: different musical material
CROSS-MODEL: only when the research question requires it

PROMOTION GATE

UNTESTED → E: a deliberately experimental input has a recorded observation.

E → D: an observed pattern supports a plausible explanation, but replication is insufficient.

D → C: the effect survives controlled repetition, the variable is isolated, conditions are preserved, and competing explanations have been tested.

Never promote directly from “sounds better” to C.
