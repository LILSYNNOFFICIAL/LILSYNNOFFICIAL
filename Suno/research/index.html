THIS IS THE LAB. Experimental Suno behavior is where we test ideas that are interesting enough to investigate but not established enough to call official behavior. The point is not to invent magic syntax. The point is to find repeatable patterns, record what happened, and separate useful evidence from one-off weirdness.

Evidence hierarchy: official Suno documentation → direct controlled testing → repeated community reports → isolated anecdotes. Suno currently describes v6 as its core model, v6-wild as the more experimental variant, and v6-mini as the faster/lightweight variant. All three support up to 8 minutes per generation. Official current-model documentation → What's new in v6 →

V6 IS THE CURRENT BASELINE

Suno's current documentation identifies v6 as the recommended general-purpose model, v6-wild as the less predictable experimental branch, and v6-mini as the faster iteration model. Older models are retired for new iterations, although existing older-model songs remain in users' libraries and can still be listened to, shared, remastered and covered. Treat V5/V4.5 material as historical evidence or a translation source rather than assuming those models remain available for fresh generation.

Research implication: every new experiment should record the exact current model. If an older prompt came from V4.5/V5, test a v6 translation rather than blindly copying its assumptions.

V4.5 / V5 → V6 TRANSLATION TEST

When migrating an older prompt, preserve the musical identity first, then rewrite the prompt around behavior and hierarchy:

OLD: genre + mood + adjective pile

V6 TRANSLATION:
IDENTITY → GROOVE → INSTRUMENT ROLES → VOCAL BEHAVIOR → ARRANGEMENT ARC → MIX RELATIONSHIPS → EXCLUSIONS

Do not assume that adding more words fixes a migration. Current community reports increasingly emphasize prioritized specificity rather than maximum prompt length.

RANDOM PHRASE / GIBBERISH EXPERIMENTATION

Another useful experiment is putting invented strings into the Styles box. The goal is not to claim that the string has a hidden meaning; the goal is to test whether arbitrary lexical shapes, punctuation, capitalization, suffixes or file-like syntax correlate with different outputs.

glitch_matrix.exe
umbrella_milkshake2.dll
velvet//signal::404
NEON_PROTOCOL::SLEEP_MODE

Change one variable at a time. If the result changes, repeat the same test before assigning a theory to the phrase.

PROMPT HIERARCHY / PRODUCER-BRIEF TEST

Current V6 community research repeatedly points toward a producer-brief approach: give the model a primary identity, then prioritize the few musical behaviors that matter most. Reports emphasize groove, instrument behavior, vocal performance, arrangement arc and mix relationships rather than an undifferentiated tag pile. This remains community evidence, not official syntax.

1. PRIMARY IDENTITY
2. GROOVE / RHYTHMIC FEEL
3. INSTRUMENT ROLES
4. VOCAL PERFORMANCE
5. ARRANGEMENT / ENERGY ARC
6. MIX RELATIONSHIPS
7. SHORT EXCLUDE LIST

Run the same song with the seven-layer version and a minimal version. If the detailed version is worse, that is useful evidence: specificity is not the same thing as verbosity.

STYLE-BOX EXPERIMENTS

Test the Style field as a hierarchy rather than a flat tag cloud. A useful experimental template is:

[PRIMARY IDENTITY] → [GROOVE / PULSE] → [KEY INSTRUMENTS + BEHAVIOR] → [VOCAL CHARACTER] → [ARRANGEMENT ARC] → [MIX RELATIONSHIPS] → [CONSTRAINTS]

Negative/exclusion language should be tested separately from the positive brief when the interface provides a dedicated exclusion control. Do not bury dozens of “no X” instructions inside the positive Style field and then assume a failure proves the model ignored you.

LYRICS-BOX EXPERIMENTS

Lyrics can carry more than literal words. Test section labels, concise performance cues, punctuation, line length, whitespace, repeated hooks, vocal cues and controlled silence. Keep cues short enough that the lyric remains readable.

[Verse 1 — intimate, restrained]
I said I was fine
but I never was

[Pre-Chorus — tension rising]
...

[Chorus — full voice, sustained final phrase]
...

Compare that with the same lyric without cues. The experiment is the comparison, not the assumption that brackets are guaranteed commands.

STRUCTURE-TAG LAB

Useful structural tags to test include [Intro], [Verse], [Pre-Chorus], [Chorus], [Post-Chorus], [Bridge], [Breakdown], [Instrumental], [Solo], [Interlude] and [Outro]. Add only the performance/arrangement detail that matters for that section.

[Intro — filtered pulse, no lead vocal]

[Verse 1 — close, restrained vocal; sparse drums]

[Pre-Chorus — bass rises; percussion opens]

[Chorus — full arrangement; wide doubles; sustained hook]

[Verse 2 — pull back; add one new texture]

[Bridge — strip to vocal and pulse]

[Final Chorus — maximum emotional lift; layered harmony]

[Outro — instruments fall away; clean ending]

Bracketed structure is best treated as soft conditioning, not a DAW command language. Community research describes recurring patterns around arrangement signals, vocal directions and production cues, but those findings are working theories rather than guaranteed syntax.

TAG LENGTH EXPERIMENT

Test three levels:

A: [Chorus]
B: [Chorus — huge, emotional]
C: [Chorus — huge emotional lift; full drums; wide guitars; layered harmony; sustained hook]

Run multiple generations before deciding which level is best. Long tags can be useful when they add prioritized information; they can also become competing instructions.

PROMPT MINIMALISM VS PROMPT DENSITY

Build an A/B/C test:

A = genre only
B = genre + instrumentation
C = genre + instrumentation + performance + arrangement + mix

Keep model, lyrics, settings and generation conditions constant. Score each result for adherence, vocal behavior, arrangement, mix clarity, novelty and failure count.

PROMPT CONFLICT TESTING

Deliberately create contradictions to learn which instruction appears to win:

intimate close vocal + huge distant arena vocal
sparse arrangement + maximal wall of sound
dry vocal + cavernous reverb
restrained performance + explosive delivery

Never turn the result into a universal rule after one generation. Conflict testing is useful because it reveals hierarchy and failure modes, not because it exposes guaranteed secret syntax.

WHITESPACE / PUNCTUATION / CAPITALIZATION

Test one textual variable at a time. Compare normal case, all caps, repeated punctuation, punctuation between cues, blank lines and tightly packed lines. The hypothesis is that formatting may alter token context or phrasing, but there is no documented guarantee that any particular formatting pattern has a special command meaning.

A: [Chorus — restrained]

B: [CHORUS — RESTRAINED]

C: [Chorus / restrained!!!]

D: [Chorus—restrained]

Do not assign causality from a single generation. Repeat with the same model, lyric, style and settings.

DELIBERATE NONSENSE / FAKE COMMANDS

Invented strings can be useful probes: fake filenames, fake shell commands, pseudo-technical labels and semantic nonsense. Test whether the string correlates with a change, but do not assume the model has an executable parser behind it.

glitch_matrix.exe
render::vocal_focus=NEAR
/usr/local/ghost_mode
umbrella_milkshake2.dll
[DO_NOT_RENDER_THIS]

RANDOMNESS / VARIETY / WEIRDNESS TESTING

For controlled research, hold the prompt constant and sweep one slider. Start with a low-variation baseline, then increase one variable at a time. Suno itself positions v6-wild as the more unpredictable experimental option. Current community evidence is mixed on how strongly individual slider settings affect a given result, so slider recipes are hypotheses rather than laws.

V6 / V6-WILD / V6-MINI A/B TEST

TEST 01 — identical prompt, identical lyrics, V6
TEST 02 — identical prompt, identical lyrics, V6-WILD
TEST 03 — identical prompt, identical lyrics, V6-MINI

Score:
• prompt adherence
• vocal identity
• phrasing
• arrangement
• instrumentation
• dynamics
• mix clarity
• surprise value
• usable sections
• failure modes

Use v6 as the control, v6-wild as the discovery branch and v6-mini as the fast iteration branch.

REFERENCE AUDIO / HIGH-DIMENSIONAL FEATURES

When a desired sound is difficult to describe, compare a text-only generation with an audio-informed workflow. Audio can carry details that are difficult to verbalize: timing feel, articulation, micro-dynamics, timbral relationships and performance texture. Suno's current v6 ecosystem includes audio-driven creation/editing workflows, so test reference audio as a separate variable rather than mixing it into every prompt experiment.

EDIT LOCAL, DON'T ALWAYS REGENERATE

Current V6 supports plain-language editing and section-level workflows. If a song is mostly right but one part fails, test local repair before throwing away the entire generation. This also improves experimental validity because fewer variables change at once.

CHORUS CONSISTENCY TEST

If repeated choruses drift, test lyric prosody and line geometry before endlessly changing production adjectives. Hold the Style prompt constant while comparing syllable density, line lengths, repeated wording, punctuation and section cues. A chorus that survives several generations is stronger evidence than one perfect take.

V6 FAILURE MODES TO LOG

Current community reports include distant or buried vocals, changing volume, disappearing instrument layers, stuttering parts, unexpected instrumentation and endings where the vocal continues beyond the perceived musical finish. These are community observations, not universal V6 behavior, but they are useful failure-log categories.

COMMUNITY PROMPT RESEARCH

Current V6 discussions are converging on a producer-oriented hierarchy, but the community also reports that some detailed prompts still fail or produce generic/flat results. That conflict is important: prompting can matter without being sufficient to overcome every model behavior. Capture both successful and failed cases.

FAILURE LOGGING

Record failures as carefully as successes. Examples: vocal buried, wrong singer texture, chorus arrives early, instruments disappear, unwanted genre drift, late-song degradation, excessive reverb, weak low end, clipped ending, repeated phrase corruption, ignored section direction.

Attach the exact prompt and settings to every claim. A “good generation” without conditions is weak evidence.

RESEARCH RULE

One weird result is a story. Three controlled repeats are a lead. A repeatable pattern across conditions is evidence.
