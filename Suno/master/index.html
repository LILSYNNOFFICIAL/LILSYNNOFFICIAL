SUNO V6 MASTER GUIDE

The canonical workflow for creating, controlling, producing, diagnosing, testing and researching Suno V6. Use this page as the map; use the linked category labs for deep work and the current-capabilities reference for the surrounding V6 ecosystem.

THE V6 OPERATING MODEL

Suno's current model family is v6, v6-wild and v6-mini. Official documentation positions v6 around control and precision, v6-wild around experimentation and less predictable results, and v6-mini around faster iteration. Treat model choice as part of the experiment, not as an afterthought.

CREATE

Build the musical identity first: genre, rhythm, instrument roles, vocal identity, performance, arrangement arc, production intent and constraints. Keep Style prompts prioritized rather than turning them into word soup.

CONTROL

When the song already has useful material, edit locally before regenerating everything. Use Extend, Replace/Edit Section, references, remix/edit workflows and other model-supported controls according to the task.

Open Control →

PRODUCE

Move from generation to production: Studio, arrangement, stems, MIDI, effects, automation, recording/editing and export. Separate generative decisions from downstream mixing decisions.

Open Produce → · Audio Engineering →

FIX / TEST

Diagnose the actual failure before changing the prompt. Log timestamps, isolate variables, compare alternatives and use local repair when it is more appropriate than full regeneration.

Open Fix / Test → · Controlled Experiments →

RESEARCH

Separate official behavior from repeated community observations, individual reproducible results, hypotheses and deliberately weird experiments. Undocumented syntax is never presented as a guaranteed API.

EXPERIMENTAL

Use symbols, punctuation, gibberish, invented syntax, contradictory descriptors and other unusual inputs as controlled variables. Weirdness belongs in the lab with evidence labels, not in the guide as fake certainty.

PROMPT ARCHITECTURE

Identity → Rhythm → Instrument Roles → Vocal Performance → Arrangement Arc → Production → Constraints. This is a practical organizing framework, not an official Suno command language. Start with the highest-value information and remove instructions that compete with the result you actually want.

STYLE

Describe the global musical identity and production target: genre, era, tempo/feel, instrumentation, vocal identity, performance character, arrangement and sonic direction.

LYRICS

Lyrics are more than semantic text. Line length, syllable density, repetition, punctuation, spacing, phonetic shape and section geometry can be tested as possible controls on phrasing and rhythm.

STRUCTURE

Use recognizable section labels and descriptive cues as soft conditioning. Treat undocumented tag behavior as experimental and test it across multiple generations.

EXCLUDE

Use exclusions to state what you do not want, then verify whether the result actually changes. An exclusion is not proof that the model will obey it deterministically.

THE RESEARCH RULE

Change one variable → generate multiple samples → compare → repeat → record failures.

Every serious claim should carry an evidence level: A official/confirmed, B repeated community evidence, C individual reproducible experiment, D interesting but unverified hypothesis, or E intentionally experimental/novel behavior.

A successful generation is not automatically a rule. A failed generation is not automatically proof that a technique never works. Record model, version, settings, prompt, lyrics, structure, reference audio, variable, control, test, repeat count, observations and confidence.

MODEL SELECTION

V6

Default starting point when you want the strongest combination of control, precision and polished output.

V6-WILD

Use when the goal is discovery, variation, unusual combinations or deliberate departure from the prompt. Capture useful surprises and bring the idea back into a more controlled workflow when appropriate.

V6-MINI

Use for fast iteration, high-volume exploration and inexpensive concept testing before committing to a full generation.

CURRENT V6 CAPABILITIES

The model is only one layer of the current Suno ecosystem. Custom Models, Voices, Suno Sounds, Remix/Edit workflows, Remaster, Advanced Stems and Studio 2.0 can materially change the correct workflow and therefore belong in the operating map.

CUSTOM MODELS

Pro/Premier users can build private models from their own rights-cleared music. Treat a Custom Model as a distinct model condition in testing.

VOICES

Voice-specific generation is separate from ordinary vocal-style prompting. Record the source, verification state, compatible model and relevant influence settings when testing it.

REMASTER

Use Remaster when the composition is already right and the desired change is mainly sonic refinement. Variation strength ranges from Subtle to Normal to High.

STUDIO 2.0

Premier Studio adds automation, effects, MIDI, advanced stems, generative editing and export workflows. It is a production environment, not simply another generation mode.

CONTROL BEFORE REGENERATION

If a song already contains a strong chorus, vocal, riff, arrangement idea or performance, do not automatically throw the entire generation away. First ask whether a local operation can solve the problem: edit/replace a section, extend from a useful point, use a reference, remix/sample, or move into Studio for production work.

This is especially important for repeatability research: changing a single section is a different experiment from regenerating the entire song.

AUDIO QUALITY DECISION TREE

GENERATION PROBLEM

First determine whether the problem is arrangement, vocal performance, frequency balance, dynamics, artifacts, stereo behavior or something else. Fix the correct layer.

LOCAL REPAIR

Prefer section-level editing when the rest of the song is already valuable and the defect is localized.

PRODUCTION

Use stems, Studio, effects, automation, MIDI or external production tools when the generated material is good but needs engineering work.
