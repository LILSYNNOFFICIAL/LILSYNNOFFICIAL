## Universal Site Shell

The site has one runtime-generated header, one navigation drawer, and one footer for every HTML page.

```text
site-global.css
       ↓
site-global.js
       ↓
┌──────────────────────────────┐
│ ONE FIXED HEADER             │
│ LS_HEADPHONES.png Easter egg │
│ hamburger                    │
└──────────────────────────────┘
               ↓
        PAGE-SPECIFIC CONTENT
               ↓
┌──────────────────────────────┐
│ ONE UNIVERSAL FOOTER         │
│ navigation + socials + legal│
└──────────────────────────────┘
```

`site-global.js` removes legacy shell markup and injects the canonical shell at runtime. This keeps older HTML compatible while preventing pages from rendering competing versions of the header/footer.

`site-global.css` owns shell geometry, responsive behavior, drawer behavior, focus states, footer presentation, the back-to-top control, homepage panel consistency, release filters, and the subtle audio control.

### Universal header

Every page uses:

- `/assets/images/icons/LS_HEADPHONES.png`
- the headphone image is intentionally clickable and links to `/special_access.html`
- the headphone image is an Easter egg, not a normal navigation label
- 52px desktop artwork and 42px narrow/mobile artwork
- fixed 72px desktop header and 64px narrow/mobile header
- universal hamburger menu
- identical positioning across homepage and secondary pages

The old `/assets/img/LS.png` header icon is no longer used by the universal shell.

### Universal menu

Canonical primary navigation:

- Home
- Music
- Releases
- Videos
- About
- Merch
- Lyrics
- Contact
- Socials

Socials and Stream are independent collapsible groups. Opening one closes the other.

### Menu accessibility

The universal shell maintains:

- `aria-expanded`
- `aria-controls`
- `aria-hidden`
- keyboard focus states
- Escape-to-close
- internal menu scrolling
- body scroll locking while the drawer is open

Do not add another global hamburger, side menu, or footer implementation.

### Universal footer

- LIL SYNN branding

## Back To Top

Every HTML page gets a floating bottom-right back-to-top control generated by `site-global.js`.

Asset:

```text
/assets/images/icons/UP_ARROWS.png
```

Behavior:

- hidden near the top of the page
- appears after scrolling down
- clicking it smoothly returns to `scrollY = 0`
- uses the current page only
- responsive positioning on mobile

## Homepage

`index.html` remains the homepage owner for page-specific content, but the universal shell owns all shared chrome.

### Music discovery

The homepage Music section is intentionally minimal:

- transparent/glass presentation
- 8 tracks instead of 9
- no redundant “Discover / discover Lil Synn / let the signal choose” copy
- one `RANDOMIZE` action
- randomized tracks are sourced from the canonical release catalog rather than a second hard-coded release database

The randomizer therefore remains tied to `release-catalog.json` and can grow with the archive.

### Spotify player

The homepage Spotify embed is deliberately taller for better listening context. It uses a responsive desktop/mobile height in `site-global.css`.

### Artist section

The Artist area is collapsed by default and converted into button-driven sections by `site-global.js`.

Each button expands its corresponding section and smoothly jumps to it. This prevents the homepage from presenting one large uninterrupted block of artist information.

### Homepage panel system

Homepage content panels now share one visual language:

- dark translucent surfaces
- subtle pink borders
- consistent rounded corners
- consistent blur
- consistent spacing
- transparent section backgrounds where appropriate

The goal is for Music, Videos, Artist, Merch, SYNN SIGNAL, and Contact to feel like parts of one system instead of unrelated cards.

## The Calm

Homepage background audio uses:

```text
assets/other/sound/Background.mp3
```

The UI name is **THE CALM**.

`site-global.js` detects the `Background.mp3` audio element and adds a subtle floating ON/OFF control. The control:

- does not dominate the page
- toggles mute state without removing the audio element
- updates its accessible label/state
- attempts playback when the user turns it back on
- waits briefly if the page-specific script creates the audio element after the global shell initializes

Browser autoplay restrictions still apply. The site cannot guarantee audible autoplay on every browser/device.

## Releases Archive

`release-catalog.json` is the canonical release database. It owns:

- catalog order
- release groups
- release type
- track lists
- Spotify destinations
- Apple Music destinations when known
- track-level Spotify destinations
- artwork mapping through the releases renderer
- SoundCloud destination for `Touching to the North`

Current catalog order begins:

1. `Never Known`
2. `HOME (ACOUSTIC VERSION)`
3. `I DID IT AGAIN`
4. `Rescue You (Acoustic Version)`
5. `Somewhere In-Between`

### Release filtering

`releases.html` now has a filter bar generated by `site-global.js`.

Users can filter by:

- **Release type:** All, Albums, EPs, Singles
- **Platform:** All, Spotify, Apple Music, SoundCloud
- **Sort:** Catalog order, A → Z, Z → A, Release type
- **Reset:** returns to the canonical catalog view

Filtering operates on the rendered release cards and does not create a second catalog.

### Artwork sizing

Single-release artwork is intentionally constrained so the first entries do not become oversized visual blocks. Collection artwork remains part of the release card layout.

### Streaming links

Every normal release track is expected to expose both Spotify and Apple Music access.

For missing Apple Music destinations, the current global compatibility layer supplies an Apple Music search link for `LIL SYNN + track title`. This guarantees an Apple Music action without inventing a false direct track URL.

When exact Apple Music track URLs are supplied, they should be added to `release-catalog.json` and the catalog should become the permanent source of truth for those destinations.

### Touching to the North exception

`Touching to the North` is the deliberate exception to the Spotify/Apple requirement.

It is treated as **SoundCloud-only** and points to:

```text
https://soundcloud.com/lilsynnofficial/sets/touching-to-the-north
```

The compatibility logic removes the normal track streaming buttons for this release so it does not incorrectly imply Spotify or Apple availability.

### Release order

The catalog `order` array remains authoritative. Runtime normalization uses that order before release filters are applied, so the default view remains the intended catalog sequence.

## Special Access

## Accessibility and Responsive Rules

Preserve:

- meaningful image alt text
- keyboard focus states
- `aria-expanded`, `aria-controls`, and `aria-hidden`
- Escape-to-close
- reduced-motion behavior
- mobile-friendly drawer sizing
- `playsinline` for video
- no horizontal overflow
- internal scrolling for long navigation menus
- accessible labels for floating controls

Test large desktop, standard desktop, tablet, mobile, and narrow mobile.

## Git / Deployment QA

Before committing website changes:

1. Inspect changed files.
2. Review the complete diff.
3. Confirm no unrelated files changed.
4. Validate HTML/JS/CSS syntax where applicable.
5. Check console errors and failed network requests.
6. Verify artwork, WebM, and audio assets.
7. Verify the universal shell exists on every HTML page.
8. Verify exactly one rendered header, one rendered side menu, and one rendered footer.
9. Verify the headphone Easter egg routes to Special Access.
10. Verify the UP_ARROWS control appears and returns to the top.
11. Verify The Calm can be muted/unmuted.
12. Verify release filters and reset behavior.
13. Verify the catalog remains in canonical order by default.
14. Verify Touching to the North remains SoundCloud-only.
15. Verify responsive behavior.
16. Commit with a meaningful message.
17. Confirm Vercel deploys the intended commit.
18. Test the actual production site.

A Vercel deployment being `READY` does **not** by itself prove visual or functional correctness.

### Deployment rate limits

If Vercel reports an account deployment allowance such as `api-deployments-free-per-day`, do not create meaningless commits or spam retries. Keep `main` at the validated source state and retry only when deployment capacity is available.

## Automated Validation

`.github/workflows/fix-homepage.yml` validates required architecture/assets and canonical release data. It also handles legacy `BG2.webm` normalization where configured.

`.github/workflows/inject-site-global.yml` keeps the universal shell cache-buster current where required.

## Maintenance Rules

1. Fix the system that owns the behavior.
2. Do not create parallel implementations of navigation, footer, release data, artwork, media playback, or background video.
3. Do not add page-specific selectors that redefine global shell geometry.
4. Keep global links and social destinations centralized in `site-global.js`.
5. Keep global shell CSS centralized in `site-global.css`.
6. Keep release data centralized in `release-catalog.json`.
7. Keep exact streaming URLs in the catalog when known.
8. Use Apple Music search fallbacks rather than inventing direct Apple Music URLs.
9. Keep page-specific functionality in the page or its dedicated script.
10. Never claim live deployment or browser verification unless it was actually verified.

The design goal is simple:

> **One header to rule them all. One menu to rule them all. One footer to rule them all. One source of truth.**
